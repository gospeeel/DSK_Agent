# Переход frontend с моков на backend

Актуально на 12 сентября 2026 года. HTTP-контракты описаны в [FRONTEND_INTEGRATION.md](./FRONTEND_INTEGRATION.md).

## Реализовано

- Cookie-аутентификация, роли `user`, `manager`, `supervisor`, выход и очистка server-state.
- Клиенты, обращения, история сообщений, сделки и их допустимые переходы статусов.
- Каталог ЖК, корпусов, квартир и этапов строительства; создание записей менеджером и редактирование руководителем без удаления.
- Семь детерминированных шаблонов этажей: один корпус и этаж всегда получают ту же совместимую геометрию, фактические ID/цены/статусы приходят из backend.
- Карточка объекта с квартирами, ходом строительства, парковками, кладовыми и имитацией ERP: события, остатки материалов, график ЖБИ.
- Реестр КП: серверный расчёт, генерация AI, версии, согласование/отклонение руководителем, PDF, SMTP-отправка вложения и запись результата доставки.
- Версионируемая матрица скидок по корпусу и роли. При отсутствии действующей записи используется конфигурационный лимит backend.
- Приватный анализ переписки менеджера: факты, возражения и черновик ответа не попадают в клиентский чат без действия менеджера.
- Конкурентный анализ с ценой за м², районом, источником и датой наблюдения.
- Клиентские уведомления о строительных рисках, staff-напоминания и серверный аудит AI-действий.
- AI получает ERP-риски через `construction.events.get`. Точная дата сдачи разрешена в prompt только при `exact_delivery_date_allowed=true`.
- AI-интерфейс и HTTP endpoint доступны только сотрудникам; клиентский маршрут закрыт guard-ом.
- Идемпотентный `backend/seeds/demo.sql` покрывает роли и все поддерживаемые состояния основных сущностей; `backend/scripts/seed-demo.sh` применяет его к текущему Docker volume.

Frontend соблюдает FSD: страницы компонуют widgets/features, запросы и бизнес-состояние находятся в `model`/`api`/`lib`, UI получает данные и события. Pinia используется для состояния сессии/UI, TanStack Query — для server state.
